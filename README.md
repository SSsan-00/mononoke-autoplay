# もののけリミット 自動プレイヤー

公開ゲームをChrome/Chromiumで開き、ゲームのソースファイルを変更せずに自動操作するNode.jsプログラムです。

対象: https://aigengames.pages.dev/Games/SurviveLimitMononoke/

## 最初に動かす

Node.js 22以上を用意し、このフォルダをターミナルで開いてください。
旧版から更新する場合は、更新版ZIPを別フォルダに展開して以下を実行します。旧版の`runs/`は残せます。
macOS・Windowsで利用できます。今回の実動検証環境はLinuxです。

```bash
# 配布物のロックファイルどおりに依存ライブラリをインストールします。
npm ci

# Playwrightが操作するChromiumをダウンロードします。
npm run setup

# 盤面L・6種類各5体・30秒・ライフ1を、先読みで自動プレイします。
npm start -- --hard
```

ゲーム用のブラウザが開き、自動で開始してキャラクターが動きます。
終了すると結果画面が残ります。Chromeを閉じるか、ターミナルでCtrl+Cを押すと終了します。
通常のブラウザとは別の一時的なブラウザ環境を使い、ログイン情報などを再利用しません。

既にインストール済みのGoogle Chromeを使う場合、`npm run setup`の代わりに次を実行できます。

```bash
# npm ciを済ませてから実行します。
npm start -- --channel chrome --hard
```

## 各キャラ5体で挑戦する

```bash
# 最初は盤面L。敗北時は通常の新規プレイを最大3回まで試します。
npm start -- --hard

# ライフ2で試す場合。
npm start -- --hard --lives 2

# 小さい盤面S・ライフ1で30秒に挑戦する場合。
npm start -- --hard --field S

# 小さい盤面S・ライフ1で最長の120秒に挑戦する場合。
npm start -- --hard --field S --time 120

# 試行を増やす場合（成功したら終了します）。
npm start -- --hard --attempts 10
```

`--hard`は指定した方式（標準は`planner`）で、盤面L・各5体（合計30体）・30秒・ライフ1を自動設定します。
旧版と同じシード1～10を、原本のゲームルールで比較しました。

| 条件（全6種類各5体） | 旧版v1.1.0 | 新版v1.2.0 |
| --- | --- | --- |
| L・ライフ1・30秒 | 6/10 | 10/10 |
| S・ライフ2・30秒 | 4/10 | 10/10 |
| S・ライフ1・30秒 | 0/10 | 10/10 |
| S・ライフ1・120秒（シード1～3） | 0/3 | 3/3 |

追加のシード11～20でも、S・ライフ1・30秒は旧版0/10、新版10/10でした。
少数の固定シードによる結果で、全シードでの成功や一般の成功率を保証する数値ではありません。
ブラウザでもL・ライフ1・30秒、S・ライフ1・30秒と120秒を、通常のシードで無被弾クリアしました。
この比較表はブラウザ描画を含まない固定ステップ検証です。ブラウザでの実測・失敗も含む記録は`verification/VERIFICATION.md`にあります。

再試行ではゲームの設定画面から開始し、ゲーム自身が新しいシードを作ります。
同じシードを再実行する「同条件で再出陣」は使いません。乱数やライフを変更しません。

## 誰がプレイするか

- `planner`（標準）: 終了まで生存できる経路を探索します。見つからなければ8回先の行動を比べ、その場で判断します。API料金はかかりません。
- `heuristic`（旧方式・明示的に指定）: プログラムの回避ロジックが判断します。Jevは呼び出しません。
- `jev`: 終了までの事前探索を省き、20回先・最大24候補の短期予測を使います。予測で最良と近い候補に絞ってJevが選びます。候補が1つならAPIを呼ばずに実行します。APIキーと利用可能な残高・権限が必要です。

いずれの方式も人間が移動を操作する必要はありません。全条件でのクリアは保証しません。
このプロジェクトはJavaScriptで実装しています。Rust版ではありません。

## Jevについて

ランダムとJevの最後の選択だけを比較するissue #1の実験器を追加しました。生存候補の定義、固定シード・ブラウザ測定、API上限、ログと再集計の手順は[比較実験の説明](verification/SURVIVAL-COMPARISON.md)を参照してください。

Jevは任意で利用できます。通常起動はAPI不要のローカル版です。

```bash
# 全経路の事前探索をせず、短期予測でJevの候補を絞ります。
npm run jev -- --hard --attempts 1 --max-calls 300
```

短期予測にも計算時間はかかります。判断間隔は100msを推奨します。300msへ延ばすと回避の機会が減ります。
長期の袋小路まで避けられるとは限らず、全経路探索と同等の攻略率は保証しません。詳細・従来方式への切り替えは`JEV.md`を参照してください。

## 敵やライフを自分で設定する

```bash
# 設定画面を表示し、最大5分間、ゲーム開始を待ちます。
npm start -- --manual

# 条件を設定してから、その場の先読みだけでプレイさせる場合です。
npm start -- --manual --rolling
```

Chromeの設定画面で敵の数、制限時間、ライフ、盤面を設定し、「百鬼結界にいざ出陣」を押してください。
ゲーム開始後の移動は自動です。観戦中に手動でキーを押すと、その入力もゲームへ届きます。
ゲーム画面を非表示にしたり、別ウィンドウへフォーカスを移すと、ゲーム自身の仕様で一時停止します。
その場合はゲームへ戻って「再開」を押してください。待機時間を過ぎると自動操作は停止します。

## 操作の仕組みと「無改変」の範囲

1. Playwrightでゲームを開きます。
2. Chrome DevTools Protocol（CDP）のデバッガへ接続します。
3. 読み込まれた`js/screens/game.js`のゲームループを調べ、条件付きブレークポイントを設定します。
4. ゲームループが止まった時に、関数内の`sim.state`をコピーします。
5. 経路探索・先読みが上下左右・待機から行動を選びます。
6. 通常のキーボード処理が呼ぶ`sim.input('left')`などへ方向を渡します。
7. デバッガを再開し、ゲーム自身の処理で時間・移動・敵・被弾を更新します。
8. 固定ステップ内で移動が終わった直後に次の判断を行い、クリアまたは敗北まで繰り返します。

公開サーバーのHTML/JSを書き換えず、ブラウザで読み込んだソースの差し替え・関数の置換もしません。
ライフ、敵、時間、乱数を直接変更しません。ゲームが既に持つ入力関数だけを呼びます。
自動操作に実際のキーイベントは使用しません。

**デバッガによる停止は、観戦時間とゲーム内の時間の関係に影響します。**
経路を探索する間も処理が止まるため、人間と同じリアルタイム条件での攻略性能を測るツールではありません。
ゲームにはフレーム間隔を最大100msへ制限し、1フレームの更新を最大5ステップに抑える処理があり、停止時間すべてがゲーム内時間になるわけでもありません。

ゲームの更新によって変数名やループ構造が変わった場合は、推測で操作せずエラーで停止します。
観戦中にゲームページを再読み込みした場合は、プログラムを再起動してください。

## 先読みの仕組み

`planner`は起動時に公開ゲームのルール用JavaScriptを取得し、Node.js側で予測専用の別コピーを動かします。
このローカルコピーにだけ、乱数状態・状態の複製用APIを追加します。ブラウザ側のゲームへは追加しません。
ゲームが公開するシードと観測した時刻、これまでの入力から同じ状態を再現し、終了までの経路を、通常128候補を残すビーム探索で探します。候補がすべて尽きた場合は、上限内で最大256候補へ広げて再探索します。
最大75万候補を調べても経路が見つからない場合、その場で最大8回先の行動を探索します。
敵の位置だけでなく、弾・攻撃予告・タイマー・回復・無敵時間など、観測対象の全項目を比較します。予測と観測が一致しなければ停止します。観戦中は移動キーを押さないでください。

複製した状態で複数の候補を試し、即死する候補を避け、被弾・敵・攻撃予告・逃げ道を評価します。
ゲームのHTML/JS/モデルは配布物に含めません。初回だけでなく起動ごとにルール取得の通信が必要です。
ゲームの更新でルール構造が変わった場合は、先読み用コードの対応が必要になります。

開始直後は経路探索のため、しばらくゲームが止まって見えることがあります。ターミナルに「経路探索中」と探索候補数を表示します。今回の固定ステップ検証では、30秒の経路探索で数秒、120秒で十数秒程度かかりました。PCの性能で変わります。
探索中もCtrl+Cで終了できます。ゲーム内の制限時間は、探索の待ち時間をそのまま加算する方式ではありません。

探索の幅を増やすと多くの候補を残せますが、計算時間が増えます。

```bash
# 終了までの経路を、通常128の代わりに256候補ずつ残して探します。
npm start -- --hard --field S --route-width 256 --route-budget 1500000

# 終了までの経路探索を省き、その場の8手先までの先読みだけで動かします。
npm start -- --hard --rolling
```

## 回避ロジックの内容

敵との距離、接触、弾の進行先、攻撃予告の発動時刻、天狗の突進、時限罠、移動を遅くするマス、回復と逃げ道を近似的に評価します。
ゲームの乱数や敵の将来行動を完全再現するものではなく、被弾・敗北も起こります。
Jevモードではこの回避ロジックを使わず、Jevの選択をそのまま採用します。盤面外への入力は拒否します。

## 記録

実行ごとに`runs/日時/`へ保存します。複数試行では`attempt-1/`などに各回の記録を保存し、ルートの`attempts.json`へ全試行の結果を残します。

| ファイル | 内容 |
| --- | --- |
| `decisions.jsonl` | 時刻、座標、ライフ、行動。先読みの方法、計算時間、候補数も記録 |
| `summary.json` | クリア・敗北、生存時間、被弾数、判断回数、条件とシード、探索設定と計算時間 |
| `result.png` | ゲーム自身の結果画面 |

APIキーやAuthorizationヘッダーは記録しません。
APIエラーなどで途中停止した場合、`decisions.jsonl`が残ることはありますが、正常終了の`summary.json`は作成しません。

## オプション

| オプション | 標準値・意味 |
| --- | --- |
| `--provider heuristic\|planner\|jev\|random` | `planner`。randomは共通生存候補の比較用 |
| `--comparison` | Jevで共通生存候補を使う比較モード（深さ20・幅24・100ms） |
| `--selection-seed N` | 比較用の選択乱数シード。ゲーム乱数とは独立 |
| `--candidate-budget N` | 比較モードで初手ごとに割り当てる探索枝数の上限 |
| `--all-attempts` | クリアしても指定試行数を続ける |
| `--hard` | 先読みでL・各5体・30秒・ライフ1、最大3回の通常プレイ |
| `--rolling` | 終了までの経路探索を省き、短期の先読みだけを使う |
| `--depth N` | 短期の探索深さ、1～20。plannerは8、jevは20 |
| `--width N` | 短期の探索で残す候補数、1～96。標準24 |
| `--route-width 128` | 最初の経路探索で残す候補数、1～256。経路が途切れたら最大256へ拡大 |
| `--route-budget 750000` | 経路探索で試す候補の上限、1～2,000,000 |
| `--field S\|M\|L` | 盤面を指定 |
| `--lives 1..5` | 初期ライフを指定 |
| `--each-enemy 0..5` | 全6種類の敵の数を指定（最大合計30体） |
| `--attempts N` | 通常1、`--hard`なら3。クリアしたら終了 |
| `--time 30\|45\|60\|90\|120` | 指定しなければゲームの初期設定 |
| `--manual` | 設定画面で人間が開始ボタンを押すまで待つ |
| `--channel chrome` | インストール済みGoogle Chromeを使用 |
| `--executable PATH` | 利用するChromium実行ファイルを明示 |
| `--interval 100` | 次の判断までに進めるゲーム内時間の最小値。移動中は判断しない |
| `--jev-direct` | 短期予測を省き、従来どおりJevだけで方向を決める |
| `--max-calls 1000` | Jevの全試行を通した送信回数の上限 |
| `--max-decisions 3000` | 1試行あたりの判断回数の上限 |
| `--output runs` | 記録の保存先 |
| `--headless` | 観戦ウィンドウを表示しない |
| `--close-after` | 終了後にブラウザを閉じる |

## テスト

```bash
# API料金が発生しない単体テストです。
npm test

# 公開ゲームへアクセスし、Chromiumで2条件の自動プレイを検証します（macOS）。
RUN_BROWSER_TESTS=1 node --test test/browser.test.js
```

PowerShellでブラウザテストを実行する場合:

```powershell
$env:RUN_BROWSER_TESTS = '1'
node --test test/browser.test.js
```

ブラウザテストは追跡敵1体と、6種類の敵を各1体の条件で実施します。
「クリアを必ず達成する」ではなく、開始・状態取得・複数マスへの移動・クリアまたは敗北・結果画面表示まで成立するかを検証します。
各5体・ライフ1・30秒のL/Sブラウザ検証（通常の乱数で最大6回ずつ試すため、必ず成功するテストではありません）:

```bash
RUN_HARD_BROWSER_TESTS=1 node --test test/hard-browser.test.js
```

120秒のS検証と、原本ルール上での旧版比較も実行できます（bash）:

```bash
RUN_HARD_BROWSER_TESTS=1 HARD_TIME=120 HARD_PROFILES='[["S","1"]]' HARD_OUTPUT=verification/v1.2-browser-120 node --test test/hard-browser.test.js
MONONOKE_ENGINE_DIR=/path/to/original/js/core node scripts/compare-planners.js 10
```

先読みエンジンの一致・複製テストは`MONONOKE_ENGINE_DIR`に取得済みの原本`js/core`を指定すると実行できます。
通常の`npm test`ではネットワークやゲームの原本を必要とするテストをスキップします。
詳しい今回の検証範囲は`verification/VERIFICATION.md`を参照してください。

## よくある起動エラー

- `Executable doesn't exist`: `npm run setup`を実行するか、`--channel chrome`を指定してください。
- `TYPESAFE_API_KEY`: Jevモードの環境変数が未設定です。料金なしで試すなら`npm start`を使います。
- `HTTP 401/403`: TypeSafeのキー・アクセス権を確認してください。ゲームサイトのエラーとは別です。
- `停止イベントが届きません`: ゲームが一時停止していないか、開始ボタンを押したかを確認してください。
- `ゲームループの構造が変わっています`: ゲームの更新に合わせたアダプター修正が必要です。

ゲーム本体や3Dモデルの著作権は各権利者に帰属します。この配布物にそれらのファイルは含めていません。
