# S盤面・30秒の失敗ケース調査

条件はS盤面、30秒、残機1、先読み20手、幅24、操作間隔100msで固定。未変更のゲーム原本シミュレーターと共通の生存候補生成器を使い、候補からランダムに選択した。Jev APIは使用していない。

採用構成: 化け狸（CHASER）10体、天狗（DASHER）10体、塗壁（JAMMER）10体。ほかの敵は0体。

探索のゲームシード2で7.6秒の敗北を発見。その後、探索に使っていないゲームシード3〜12と選択用乱数11・29で確認したところ、20試行中5試行が敗北（25%）。10種類のゲームシードのうち5種類で敗北した。同じゲームシードでももう一方の選択用乱数ではクリアした。

| 4 | 敗北（10.617秒） | クリア（30秒） |

先読み範囲で安全な候補があることは、30秒全体の成功を保証しない。探索シード2では約4.867秒時点の候補がupの1つになり、約5.083秒から生存候補が0になった。最終的に7.6秒で敗北した。有限の探索幅を使っているため、その時点であらゆる攻略経路が存在しないという証明ではない。

この構成をS・30秒固定のJev／ランダム比較に採用する。探索後に選んだ構成であり、全構成の中で最も難しいという主張やJevの優位性の証明ではない。20試行は10ゲームシードに各2回の選択乱数を適用したもので、20の独立したゲーム条件ではない。

再現コマンド:

```sh
MONONOKE_ENGINE_DIR=/tmp/mononoke-jev-check node scripts/find-failure-cases.js runs/failure-confirm-new --confirm-profile '{"CHASER":10,"DASHER":10,"JAMMER":10}'
npm run study:survival -- runs/study-hard-new --enemies '{"CHASER":10,"DASHER":10,"JAMMER":10}' --fixed-time
```

最初のコマンドのMONONOKE_ENGINE_DIRはローカルの原本キャッシュがある場合のみ指定する。原本のSHA-256: `a9d0db300437bac10b69b7e6fa2edba0fa10a55c3e5745867f0fe840d70a65e5`。ローカルの詳細記録は `runs/issue-1-failure-confirm/` と `runs/issue-1-failure-search/` に保存。
